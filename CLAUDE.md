# CLAUDE.md — Site StudioB04

Site vitrine statique et bilingue de StudioB04 : React 19 + TypeScript, React Router, Tailwind 4, design system `@studio_b04/ds` (≥ 0.1.6). Pages pré-générées au build (SSG) puis hydratées. `README.md` décrit le projet ; ce fichier donne les règles pour y travailler.

## Règles du projet (décidées par le propriétaire)

- **Aucune bibliothèque externe sauf absolue nécessité.** Dépendances actuelles : `react`, `react-dom`, `react-router`, `@studio_b04/ds` ; en développement : Vite, `@vitejs/plugin-react`, TypeScript, Tailwind (`tailwindcss`, `@tailwindcss/vite`), Vitest, jsdom, Testing Library. N'en ajouter aucune sans accord.
- **React Router :** utiliser le paquet `react-router` (v8). `react-router-dom` n'est plus qu'une façade de la v7.
- **Langues :** français à la racine (`/`), anglais sous `/en/`, avec **une adresse traduite par langue** (`/mentions-legales/` et `/en/legal-notice/`) : le `slug` de chaque page est dans les JSON, à côté de ses textes. Pas de redirection selon la langue du navigateur. Seulement français et anglais.
- **Routes :** déclarées à la main dans `src/router/Router/Router.tsx` (une `<Route>` par page, style classique de React Router), jamais générées par une boucle sur `getAllRoutes()`. Les pages sont identifiées par `RouterEnum` et leur adresse vient des JSON via `getSlug(RouterEnum.X, locale)` : ne jamais écrire d'adresse en dur (`path="legal-notice"`, `"/en/legal-notice/"`). Pour l'instant il n'y a que deux pages, `HOME` et `LEGAL` (les autres ont été retirées par le propriétaire, leurs textes restent dans les JSON) ; les adresses inconnues tombent sur `<Route path="*">` (page 404).
- **Textes :** toujours dans `src/i18n/locales/fr.json` et `en.json` (mêmes clés), jamais en dur dans les composants. Sous `pages`, la clé d'une page est la valeur de `RouterEnum` (`"home"`, `"legal"`) et chaque bloc a son `slug` ; `notFound` et `serverError` sont les textes des pages d'erreur (404 et 500). Les anciens blocs `digital`, `print`, `signage` et `tradeShows` restent dans les JSON sans être utilisés. **Exception provisoire :** les pages `Home` et `Legal` n'affichent que du lorem ipsum écrit en dur (demande du propriétaire), de même que les libellés des liens d'évitement de `GlobalLayout` ; à remplacer par des clés quand le contenu arrivera.
- **Lecture des textes :** `const { t } = useI18n();` puis `t("pages.notFound.heading")` ou `t("common.copyright", { year })` ; hors React (balises du `<head>`), `translate(locale, key, params)`. Les paramètres s'écrivent `{{nom}}` dans le JSON. Les clés sont typées (`MessageKey`) : une clé construite (`` t(`pages.${id}.navLabel`) ``) doit rester un type de clé valide. `messages` n'est lu que pour les listes (par exemple `pages.legal.sections`, inutilisée pour l'instant). Pas de bibliothèque d'internationalisation.
- **Navigation sans rechargement :** `GlobalLayout` est une route de layout unique (`<Outlet />`) : il reste monté d'une page à l'autre et au changement de langue (un test le vérifie). L'état global (par exemple un toast) peut y vivre ou dans `App.tsx`, au-dessus de `<Router />`.
- **Thème :** pas de bouton de changement de thème (demande abandonnée). Le site suit le réglage clair/sombre du système via les jetons du design system. Ne pas en ajouter sans demande.
- **Préprod = GitHub Pages**, déployée à chaque push sur `main` par `.github/workflows/deploy-preprod.yml` (typecheck + tests, puis build avec `VITE_NOINDEX=true`). Le site peut donc être servi sous un sous-dossier (`/Website/`) : voir « Sous-dossier d'hébergement » plus bas. Ne pas changer le déclencheur ni l'hébergement sans demande.
- **Tests unitaires** pour tout comportement ajouté ou modifié.
- Les documents, textes et échanges sont en français.

## Commandes

```bash
npm install
npm run dev          # Vite, http://localhost:5173 (réseau local inclus), sans pré-rendu
npm run build        # build:client + build:server + prerender → dist/client
npm run preview      # sert dist/client
npm run test:run     # Vitest, une exécution (npm test = mode watch)
npm run typecheck    # tsc --noEmit
```

Avant de livrer : `npm run typecheck && npm run test:run && npm run build`, puis `npm run preview` et vérifier dans le navigateur : aucune erreur console, navigation sans rechargement, page 404 sur une adresse inconnue. Si le changement touche aux liens, aux chemins ou aux ressources, refaire aussi le build en mode préprod (`BASE_PATH=/Website VITE_SITE_URL=https://studiob04.github.io/Website VITE_NOINDEX=true npm run build`, puis `BASE_PATH=/Website npm run preview`, sur http://localhost:4173/Website/).

## Architecture

- `index.html` : modèle du build, repères `<!--app-head-->` et `<!--app-html-->`.
- `scripts/prerender.ts` : importe le module serveur, appelle `render(url)` pour chaque route de `getAllRoutes()`, écrit `dist/client/<chemin>/index.html`, plus `404.html`, `sitemap.xml`, `robots.txt`, puis supprime `dist/server`. En mode `NOINDEX` (préprod) : pas de `sitemap.xml`, et `robots.txt` sans `Disallow` ni ligne `Sitemap`. Exécuté par Node directement (TypeScript sans compilation).
- `src/entry/server.tsx` : `render(url)` = `prerender` de `react-dom/static` + `StaticRouter`, renvoie `{ html, head, locale }`. `build:server` le compile en `dist/server/server.js` (Vite nomme le fichier d'après l'entrée, sans le dossier) : `scripts/prerender.ts` lit ce chemin, donc déplacer ou renommer l'entrée impose de mettre à jour `package.json` et `prerender.ts`. Le `StaticRouter` reçoit `basename={BASE_URL}` et l'adresse préfixée par `BASE_URL`.
- `src/entry/client.tsx` (chargé par `index.html`) : `hydrateRoot` si la page contient déjà du HTML, sinon `createRoot` (cas du serveur de dev). `BrowserRouter` reçoit `basename={BASE_URL}`.
- `src/router/` (import `@/router`) : `RouterEnum.tsx` liste les pages par identifiant (une entrée par page, identique dans toutes les langues ; c'est aussi la clé de la page dans les JSON). `routes/routes.ts` en dérive `PageId` (= `RouterEnum`), `pageIds`, `mainNavPages`, `servicePages`, `getSlug(pageId, locale)` (adresse traduite lue dans les JSON, vide pour l'accueil), `getPath(pageId, locale)` (français sans préfixe, autres langues préfixées), `getAlternates`, `findPage`, `getLocaleFromPath` et `getAllRoutes` (réservée au pré-rendu, au sitemap et aux tests). `index.ts` ré-exporte ces deux fichiers et le composant `Router`.
- `src/router/Router/Router.tsx` : composant `Router` (export par défaut, ré-exporté par `@/router`). Rend `<Routes>` avec `<Route element={<GlobalLayout />}>` qui contient une route de layout sans adresse, `<Route element={<PageErrorBoundary />}>`, elle-même contenant `pages("fr")` sous `<Route path="/">`, `pages("en")` sous `<Route path="en">` et `<Route path="*" element={<ErrorPage status={404} />}>` pour la 404. `pages(locale)` écrit à la main un `<Route index>` (accueil) et une `<Route path={getSlug(RouterEnum.X, locale)}>` par autre page (aujourd'hui `LEGAL`) : une seule liste pour toutes les langues. Elle est appelée comme une fonction, pas comme un composant (un composant autour de `<Route>` est refusé par React Router). Il contient aussi `useDocumentUpdate` : à chaque navigation, met à jour `lang`, le titre et la description, et place le focus sur le `h1` après un changement d'adresse (jamais au premier rendu).
- `src/App.tsx` : déduit la langue de l'adresse (`getLocaleFromPath`), la fournit à `I18nProvider` et affiche `<Router />`. Rien d'autre : les routes sont dans `Router.tsx`.
- `src/head/index.ts` (import `@/head`) : `renderHead()` génère les balises SEO au build, **uniquement côté serveur** (jamais appelée dans le navigateur). React Router ne gère pas le `<head>`. Côté client, seuls `lang`, le titre et la description suivent la navigation (`useDocumentUpdate` dans `Router.tsx`, via `getPageMeta`) ; canonical, `hreflang`, Open Graph, `robots` et JSON-LD restent ceux de la page d'arrivée. Choix du propriétaire : le HTML pré-rendu de chaque adresse est correct, c'est ce que lisent les moteurs de recherche. Ne pas synchroniser le reste du `<head>` côté client sans demande. Ajoute `<meta name="robots" content="noindex">` sur la 404 et, si `NOINDEX`, sur toutes les pages.
- `src/config.ts` : `SITE_URL` (`VITE_SITE_URL`, défaut `https://www.studiob04.fr`, sous-dossier compris), `BASE_URL` (`import.meta.env.BASE_URL`, défini par `BASE_PATH` dans `vite.config.ts` : `/` ou `/Website/`) et `NOINDEX` (`VITE_NOINDEX === "true"`).
- `.github/workflows/deploy-preprod.yml` : push sur `main` → `npm ci`, `typecheck`, `test:run`, `build` avec `VITE_SITE_URL` et `BASE_PATH` issus de `actions/configure-pages` (`base_url`, `base_path`) et `VITE_NOINDEX=true`, puis publication de `dist/client` (`upload-pages-artifact` + `deploy-pages`).
- `src/layouts/` (import `@/layouts`, fichiers tenus par le propriétaire) : `GlobalLayout/GlobalLayout.tsx` est la route de layout. Propriétés `header`, `footer`, `subfooter` (toutes `true` par défaut). Il rend les liens d'évitement (`SkipLink` de `@studio_b04/ds/uikit`, libellés en dur), `Header`, `<main id="main">` qui contient l'`<Outlet />`, `Footer` et `SubFooter` (leurs textes sont encore du lorem ipsum). Mise en page : `GlobalLayout.css` (grille sur `100dvh`, défilement dans la zone centrale). Le test est à côté (`GlobalLayout.test.tsx`). La langue (`I18nProvider`) vient de `App.tsx` ; `lang`, titre, description et focus sont gérés par `Router`.
- `src/pages/` (import `@/pages`) : `Home` et `Legal` (un `h1 tabIndex={-1}` et un paragraphe de lorem ipsum, en dur) et `Error/Error.tsx`, composant `ErrorPage` (propriété `status`: `404` par défaut ou `500`) : titre, texte et lien de retour à l'accueil (`getPath(RouterEnum.HOME, locale)`) lus dans `pages.notFound` ou `pages.serverError`. Le dossier s'appelle `Error` mais le composant `ErrorPage`, pour ne pas masquer l'`Error` global de JavaScript.
- `src/router/ErrorBoundary/ErrorBoundary.tsx` : `PageErrorBoundary`, route de layout placée **dans** `GlobalLayout` : une erreur de rendu d'une page affiche `ErrorPage status={500}` à la place de la page, sans perdre l'en-tête ni le pied de page. La limite est identifiée par l'adresse (`key={pathname}`) : elle se réinitialise donc à la navigation suivante. Les erreurs 500 n'existent que dans le navigateur (rien n'est pré-généré ; une erreur de rendu au pré-rendu fait échouer le build).
- `src/components/AppLink/AppLink.tsx` : `Link` du design system + `useHref` (href avec le sous-dossier) + `useLinkClickHandler` de React Router (navigation interne sans rechargement). `src/components/` ne contient plus que `AppLink` et `LanguageSwitcher` (ce dernier n'est plus affiché nulle part pour l'instant).

## Conventions de code

- TypeScript strict, `verbatimModuleSyntax` : utiliser `import type` pour les types.
- Un composant par dossier : `src/components/<Nom>/<Nom>.tsx` en `export default function`, puis une ligne dans `src/components/index.ts` : `export { default as <Nom> } from "./<Nom>/<Nom>";`. Les fichiers propres au composant (test, styles) vont dans son dossier. Même organisation pour les pages (`src/pages/<Nom>/<Nom>.tsx` et `src/pages/index.ts`) et pour les layouts (`src/layouts/<Nom>/<Nom>.tsx` et `src/layouts/index.ts`).
- Un module de plusieurs fichiers vit dans un dossier avec un `index.ts` : `src/router/` (`index.ts` ré-exporte `Router/Router.tsx`, `routes/routes.ts` et `RouterEnum.tsx`), `src/head/` (le code est dans `index.ts`), `src/i18n/` (`index.tsx` et `locales/`). On l'importe par le dossier (`@/router`, `@/head`, `@/i18n`), jamais par un fichier interne (`@/router/routes/routes`). Son test est à côté du fichier testé (`src/head/head.test.ts`, `src/router/routes/routes.test.ts`) et importe, comme le reste, par `@/…`.
- Imports : tout ce qui remonte dans l'arborescence passe par l'alias `@/` (`@/i18n`, `@/router`, `@/head`, `@/config`), jamais par `../../…`. Les composants, les layouts et les pages s'importent via leur fichier d'index : `import { AppLink } from "@/components";`, `import { GlobalLayout } from "@/layouts";`, `import { Home } from "@/pages";`. Les imports dans le même dossier restent relatifs (`./server` depuis `src/entry/server.test.tsx`). Exception : à l'intérieur de `src/components` et de `src/router`, importer un autre fichier du même module par chemin relatif (`../AppLink/AppLink`, `../RouterEnum`, `../ErrorBoundary/ErrorBoundary`), jamais par l'index (risque de dépendance circulaire). `Router.tsx` importe pourtant `@/router` : le cycle est sans effet parce que ces imports ne servent qu'au rendu (dans `pages()` et `useDocumentUpdate`) ; ne pas y ajouter d'import utilisé à l'évaluation du module (constante de module, par exemple).
- Alias d'import : `@/*` → `src/*`. Un alias se déclare une seule fois, dans `paths` de `tsconfig.json` ; Vite, Vitest et le pré-rendu le lisent grâce à `resolve.tsconfigPaths: true` dans `vite.config.ts` (ne pas ajouter de `resolve.alias`).
- Styles : classes Tailwind du thème du design system, pas de CSS maison. `src/styles/global.css` (fichier tenu par le propriétaire, ne pas le modifier sans demande) ne contient que l'ordre des couches et les imports ; les styles de base (couleurs du `body`, anneau de focus) viennent du reset du design system. Pour un jeton sans classe : `bg-(--ds-bg-inverse)`, `text-(color:--ds-text-inverse)`.
- Accessibilité (priorité du projet) : repères de page, navigations nommées, `aria-current`, `lang` sur les liens de langue, anneau de focus visible (fourni par le reset du design system), focus géré après navigation.
- Tests : Vitest + Testing Library, à côté du code. Chercher par rôle et nom accessible, pas par classe CSS. Les tests de rendu serveur commencent par `// @vitest-environment node`. `config.ts` lit l'environnement à l'import : pour tester `VITE_NOINDEX` ou `BASE_URL`, utiliser `vi.stubEnv(…)`, `vi.resetModules()` puis un `import()` dynamique du module testé, et `vi.unstubAllEnvs()` + `vi.resetModules()` dans `afterEach`. `src/entry/client.test.tsx` suit ce schéma pour `entry/client.tsx`, qui démarre l'application dès son import : `react-dom/client` y est enveloppé par `vi.mock` pour savoir si `createRoot` ou `hydrateRoot` est appelé et relever les erreurs d'hydratation récupérables ; utiliser le `act` de `@testing-library/react` (celui de `react` affiche un avertissement).

## Sous-dossier d'hébergement

La préprod vit sous `https://studiob04.github.io/Website/` (sauf domaine personnalisé), donc rien ne doit supposer que le site est à la racine :

- Liens internes : uniquement `Link`/`NavLink` de React Router ou `AppLink`, avec un chemin issu de `getPath()`. Jamais de `<a href="/…">`, de `window.location` ou de chemin en dur : ils ignoreraient le sous-dossier. Seules les ancres (`#main`) sont libres.
- Ressources : images, polices et CSS passent par Vite (import ou `public/`), qui ajoute le `base`. Ne pas écrire `/chemin` en dur dans du CSS ou du JSX.
- `SITE_URL` contient déjà le sous-dossier (c'est `base_url` de `configure-pages`) ; les URL absolues (canonical, `hreflang`, sitemap) s'écrivent `SITE_URL + getPath(…)`, sans y ajouter `BASE_URL`.
- Le `basename` de React Router est `BASE_URL` avec son slash final, pour que le lien vers l'accueil soit `/Website/` et non `/Website`.
- Préprod : ne jamais ajouter de `Disallow` à `robots.txt` (le `noindex` ne serait plus lu) ni de sitemap.

## Pièges connus

- **Couches CSS :** garder la déclaration `@layer base, properties, theme, mozaic, utilities, components;` en première ligne de `global.css`, et les imports `@studio_b04/ds/styles` et `@studio_b04/ds/reset` dans `layer(base)` ; sinon des règles hors couche écrasent les classes Tailwind (`p-3`, `m-0`…).
- **Thème Tailwind du design system :** il supprime la palette par défaut ; l'espacement est basé sur 0,5 rem (`p-3` = 1,5 rem). Les noms (`bg-primary`, `text-brand`, `border-primary`) n'existent qu'à partir de `@studio_b04/ds` 0.1.6. Avec un lockfile, `^0.1.5` n'installe pas la 0.1.6 : utiliser `npm install @studio_b04/ds@latest`.
- **Icônes du design system :** bloquées par les navigateurs (`<use href="data:…">`). Ne pas utiliser `iconStart`, `iconEnd` ni `external` sur `Link` et `Button`. Le composant `Icon` embarque toute la bibliothèque Lucide, d'où ~1,3 Mo de JavaScript. À corriger dans le design system.
- **`StrictMode` (développement) :** les effets s'exécutent deux fois. Ne pas détecter le « premier rendu » avec un booléen : `useDocumentUpdate` (dans `Router.tsx`) compare l'adresse précédente (un test le couvre).
- **Rendu serveur :** ne pas lire `window` ni `document` pendant le rendu, seulement dans les effets.
- **Slugs :** un slug ne doit jamais être égal à un code de langue (conflit avec le préfixe `/en/`) ni à celui d'une autre page de la même langue ; des tests le vérifient. Ajouter une page : entrée dans `RouterEnum`, bloc avec `slug` dans chaque JSON, ligne dans `pages(locale)` de `Router.tsx` ; le test « renders $path » (une entrée par adresse de `getAllRoutes()`) échoue si la `<Route>` manque.
- **`PageId` est une enum de chaînes :** TypeScript refuse une chaîne littérale à sa place (`getPath("home", locale)` est une erreur). Toujours `RouterEnum.HOME`, `RouterEnum.LEGAL`…
- **Serveur de dev :** n'injecte pas les balises SEO du `<head>` ; vérifier le SEO avec `build` + `preview`.
- **Lien d'évitement :** `SkipLink` vient du design system (`@studio_b04/ds/uikit`, ≥ 0.1.6) ; il n'y a plus de version locale.
- **Pages d'erreur :** la 404 est `ErrorPage status={404}` (route `*`) et `404.html` est générée en français uniquement (`render("/404/")`). La 500 (`PageErrorBoundary`) n'est jamais pré-générée. Le rendu client d'une adresse inconnue sous `/en/` se fait en anglais : mesuré dans Chrome : sous `/en/` le HTML français de `404.html` ne correspond pas au rendu anglais, React signale l'erreur #418 (écart d'hydratation) puis refait le rendu côté client ; le résultat affiché est correct (anglais). Sous la racine, aucune erreur. À corriger avant de rendre la 404 bilingue.

## Hébergement

- **Préprod :** GitHub Pages (dépôt public, Settings → Pages → Source = GitHub Actions), mise à jour à chaque push sur `main`. Adresse par défaut `https://studiob04.github.io/Website/` ; domaine personnalisé possible via Settings → Pages (un fichier `CNAME` est ignoré avec un workflow Actions), puis relancer le workflow. Les pages sont publiques (noindex, mais lisibles).
- **Production :** pas encore choisie. Le résultat est un dossier statique (`dist/client`). Il faut un hébergeur qui renvoie `404.html` avec le statut 404.
- **Variables de build :** `VITE_SITE_URL` (défaut `https://www.studiob04.fr`), `BASE_PATH` (défaut vide, lu par `vite.config.ts`), `VITE_NOINDEX` (défaut non défini).
